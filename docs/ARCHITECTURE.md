# Архитектура Prompt Lab AI

## Принципы
- Flutter/Dart: UI и прикладная логика.
- Kotlin: Android-интеграции (Share Intent, SAF, WorkManager, биометрия, системная информация).
- AI Runtime: отдельный интерфейс, не связывающий приложение с одним движком.
- SQLite: структурированные данные; семантический индекс — отдельный адаптер.
- Локальность: пользовательские данные и AI-запросы остаются на устройстве, если пользователь отдельно не разрешил иное.

## Слои
1. UI — экраны и виджеты.
2. Application Services — сценарии и координация.
3. Repositories — интерфейсы доступа к данным.
4. Data — SQLite и файловое хранилище.
5. Platform — Android/Kotlin-интеграции.
6. AI — Runtime API, Model Manager и адаптеры движков.

## Поток
UI -> Application Services -> Repositories -> Local Storage / Android Platform / AI Runtime.

## AI Runtime
Основной кандидат для GGUF — llama.cpp. Vision подключается отдельным адаптером после проверки совместимости конкретной модели и backend. Размер модели, квантование и контекст выбираются по доступным ресурсам.

## Ограничения
- «Обучение» на промтах означает извлечение правил, индексацию и retrieval, а не автоматическое изменение весов LLM.
- Android ограничивает фоновую работу и доступ к буферу обмена.
- Статический анализ кода не заменяет компиляцию и запуск.
- Одновременно держать несколько тяжёлых моделей в RAM смартфона не предполагается.
